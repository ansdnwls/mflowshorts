# 단계별 진행 현황

## 1. 분석·대본 기능 통합

`codex/scene-analysis`에는 장면·음성 추출, 명시적 분석 검토, 검토된 근거에 연결된 대본 초안과 제작 반영이 구현되어 있다. 조회 당시 main은 `f9691b0`, 분석 브랜치 첫 커밋은 `8a85690`이다. 자동으로 main에 병합하거나 환경을 게시하지 않는다. Claude가 main을 수정 중이라면 브랜치 변경을 검토하고 통합한다.

검증: 전체 테스트 69개 통과·1개 선택 의존성 테스트 건너뜀. 실제 영상으로 프레임/WAV 추출, 수동 분석 검토, 로컬 초안 수정, 근거 확인, 명시적 대본 교체, 자막 시간 변환, 승인 해제, MP4/ZIP 생성을 브라우저에서 확인했다. AI 응답 형식·시간 근거 검증은 모의 응답 기반이다.

## 2. 실제 AI 품질 검증 — 필요한 다음 작업

`MFLOW_AI_KEY`를 보안 설정에 등록하고 `api.openai.com` 접속이 실제로 허용된 뒤 실행한다. 현재 런타임에는 키가 없고 해당 도메인 허용도 적용되지 않았다. 이미 초안에 요구사항은 저장했으므로 중복 키를 만들거나 키를 채팅에 요청하지 않는다.

실제 영상 1편으로 원음 전사·화면 관측·화면 문자·추정 구분·대본 각 문장의 근거를 비교한다. 잘못된 의도/관계/원인 추정, ASR 오인식, 빠른 동작 누락을 기록한다. 영상 속 사건을 외부 맥락까지 확인했다고 간주하지 않는다. AI가 그럴듯한 문장을 생성했다는 이유로 검토 완료로 처리하지 않는다.

## 3. 승인 대본의 한국어 내레이션

음성 제공자와 실제 비용/권한을 확인한 뒤 구현한다. 승인한 대본 버전의 해시와 음성 파일을 연결하고 대본 변경 시 음성을 무효화한다. 원음과 생성 음성을 구분하며, 무음/원음 유지 프로젝트는 기존 경로로 계속 제작할 수 있게 한다. 아직 구현하지 않았다.

## 4. 음성 기준 자막·장면 정렬

TTS의 실제 재생 길이와 단어/문장별 시간을 사용해 자막을 배치한다. 현재 근거 장면의 시간과 생성 음성 길이가 맞지 않으면 속도/컷/대본 수정이 필요하다고 표시한다. 자막을 균등 분할한 결과를 음성 동기화라고 부르지 않는다.

## 5. 제작 품질과 발굴 자동화

여러 원본 비율과 길이, 원음/무음, 한국어/영어/중국어 입력에서 사실·자막·장면 일치와 잘림을 확인한다. 이후 실제 네트워크/로그인 조건이 충족된 Douyin/TikTok 수집·다운로드를 재검증하고, 중복 소스와 원본 후보 연결을 확장한다. 기존 플랫폼 접속 성공이 입증된 상태는 아니다.

## 검증 소재 보관함 추가

성과 조건 일괄 보관, 원본 통계 스냅샷 보존, 흥행 가설·새 해석·사용 근거, 공통 원본 링크 수동 그룹, 제작 프로젝트 연결, 재가공 성과 수동 스냅샷을 구현했다. 실제 장면 중복 자동 탐지와 게시물 성과 자동 갱신은 미구현이다. 현재 전체 테스트는 76개 통과·1개 선택 의존성 건너뜀이며, scripts/materials_smoke.py의 브라우저 흐름이 통과했다.

## 내레이션 단계 업데이트

승인 대본의 음성 업로드·정규화·TTS 연결·문장 구간별 실제 길이·명시적 선택·재승인·렌더링·WAV 내보내기를 구현했다. 업로드 음성은 예상 배치를 직접 검토해야 한다. 실제 MP4 오디오 교체는 검증했고 TTS 실호출·한국어 품질은 키가 없어 미검증이다. 다음 검증은 실제 영상/AI 음성의 장면-대사 일치와 발음·자막 품질이며, 단어 수준 정렬과 장면 자동 재편집은 아직 구현하지 않았다.
